# 作弊 MCTS AI

基础版对手，明确知道双方当前手牌、袋中剩余币组成和弃置区；不会利用真实袋序、游戏种子或随机数状态预测未来抽币。网页显示“作弊 MCTS AI”，AI 的私有输入不会发送给玩家客户端。

当前版本使用启发式 rollout、七项截断评价和精确后继树复用。没有神经网络或训练依赖。

```python
num_simulations = 5000
rollout_depth = 120
c_uct = 1.4
workers = 16  # 按可用 CPU 数下调
```

网页每次决策新增 5000 次回传，没有时间截停；只有一个合法行动时直接返回。rollout 深度指离开搜索树后的行动数，不包含树内选择路径。终局胜负记 ±1，未到终局时按用户提供的加权特征评价，不再统一记 0。

调用方式：

```python
from warchest.cheat_mcts import SearchMemory, choose_cheat_mcts_action

memory = SearchMemory()  # 同一方、同一局的后续决策重复使用
move = choose_cheat_mcts_action(
    state, actions, rng,
    num_simulations=5000, rollout_depth=120, c_uct=1.4, workers=16,
    memory=memory,
)
```

搜索复用现有规则引擎。玩家节点使用 UCT，机会节点按真实概率采样；没有抽币的行动对应单一机会结果。每步模拟重新采样未知袋序，保留当前已知手牌。匹配实际后继状态时保留子树统计，抽到未见过的组合时可以冷启动。

## 共享树异步回传

协调线程独占树的选路、机会结果采样、扩展和回传。选出一条路径后，为路径节点增加 `in_flight`，将规范化局面与独立随机种子提交给进程池；工作进程只运行启发式 rollout，返回收益、是否终局与行动步数。任一任务完成即撤销临时占用、更新真实访问次数与收益，并补发任务，不等待整批结束。

玩家节点选择使用 `(sign * W - in_flight) / (N + in_flight)` 加 UCT 探索项；`sign` 由该节点实际行动方相对根玩家决定。因此虚拟损失对任何行动方都是暂时悲观的，不会把对方节点变成合作节点。机会节点仍只按概率采样。最终选择和统计仅使用完成模拟的真实 N/W。

正常决策严格完成指定新增次数；取消时不再提交，取消排队任务并清理全部临时占用。已经运行的工作任务可完成当前有限深度 rollout，但不能更新树或真实对局。线程内收到异常也清理占用；损坏的进程池在下次使用时重建。树的修剪仅在搜索结束、占用清理之后进行。

异步完成顺序依赖调度，即便随机种子相同也不保证完全相同决策。低层 API 保留 `workers=1`、512×16 默认值以兼容串行诊断；可显式传参切换，固定串行预算用于可复现测试。网页显式采用上面的 5000×120 配置。

## 网页与生命周期

`ai_level="cheat_mcts"` 支持基础版入门、随机、自选与 BP；BP 仍随机禁选。扩展配置在前后端均禁用。随机 AI 和旧 `basic` / `mcts` 请求兼容行为保持不变，既有随机房间不会自动变成作弊对手。

后台线程协调，页面继续短轮询；每个服务进程最多两个搜索任务，同一房间去重。所有房间共用一个最多 16 个工作进程的常驻进程池（按可用 CPU 数下调），不是每个房间各启动 16 个进程。搜索不持有数据库写锁，提交前核对局号、版本、行动方和结束状态。认输、再战会取消旧任务并清理缓存。

已启动的搜索可在关闭页面后完成并提交一步，下一次搜索需新的轮询触发。重启后保留已提交局面，未完成搜索及内存树重新建立。每个进程最多缓存八个房间/局号，每棵树最多 4000 个可达节点。

5000×120 使用固定次数而非时间截止，计算可能需要几十秒；时间随局面、硬件和并发负载变化。现有运行服务尚未重启，需重启加载新实现。
